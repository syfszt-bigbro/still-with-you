# 产品决定记录

## 2026-10-28：公开发行的定位

**问题**：现有私人桌面陪伴原型如何变成任何人都能安装、又不会泄露原人物隐私的程序？

**用户决定**：允许建立公开 GitHub 仓库；保留现有桌面互动、计划、计时、运动、聊天、记忆、备份等能力；增加照片导入与动作形象生成；结合 ex-skill 的人物与关系记忆逻辑；上传内容不得包含原私人原型的任何隐私；公开后必须重新下载并从零复现。

**决定**：

- 中文产品名为“她一直都在”，英文名为 “Still With You”，仓库名为 `still-with-you`。
- 首版沿用现有原生 macOS 14 / SwiftUI + AppKit 架构，优先 Apple Silicon。
- 私人照片、聊天、口述、人物资料、API Key 和生成形象只保存在用户本机。
- GitHub 只发布源代码、原创中性占位角色、虚构示例、测试和构建说明。
- API Key 存入 macOS 钥匙串；备份不包含密钥。
- 所有可能产生费用的模型调用必须由用户主动触发并在界面中说明；离线计划、计时、互动、导入和本地动作形象生成仍可用。
- 公开前必须完成敏感词、密钥、高熵字符串、媒体和绝对路径扫描；随后从 GitHub 干净克隆，重新测试和构建应用。

## 2026-10-28：继承 ex-skill 的部分

参考来源：[therealXiaomanChu/ex-skill](https://github.com/therealXiaomanChu/ex-skill)（MIT）。

保留并产品化以下思路：

1. 先由 Persona 决定态度和说话方式，再按相关性选取 Relationship Memory。
2. Layer 0 硬边界：不替现实人物突然表白、道歉或作出原材料不支持的承诺。
3. 每条记忆保留来源；AI 总结与原始证据分开。
4. “她不会这样说”等纠正立即生效，并进入独立纠正层。
5. 追加聊天或照片只做增量合并；每次人物/记忆更新都生成可回滚版本。

不直接继承的部分：

- 不把星座、MBTI 或依恋标签自动当成事实。
- 不把整份聊天记录塞进每次模型请求。
- 不允许公开仓库、日志或崩溃报告携带私人资料。
- 不用模拟强化执念，也不把陪伴者描述成现实人物本人。

## 2026-10-28：视觉方向

主题是“被一段关系改变过，但仍然向前”。界面避免纪念馆式沉重，也避免粉色恋爱模板。

- **夜航墨** `#272838`：主文字与桌面角色阴影。
- **余光蓝** `#5D7DA6`：主要操作和记忆连接线。
- **晨光杏** `#F2B278`：完成、温度和“向前”的提示。
- **薄雾纸** `#E7EBEF`：原生窗口背景。
- **苔绿** `#7A9275`：本地保存、隐私安全和完成状态。
- **校正红** `#B55252`：纠正、删除与错误状态。

标题使用系统宋体，正文使用苹方，时间与来源使用 SF Mono。唯一的视觉签名是一条“痕迹线”：它从导入材料开始，经过人物、记忆和纠正，最后绕到桌面角色旁；不是装饰，而是显示每一步资料如何成为可追溯的陪伴。

## 2026-10-28：历史原文、说话人确认与语音

**问题**：导入聊天时强制生成总结会把推断伪装成事实；旧版还会沿用上一次的说话人映射。公开版的复刻声音入口也曾被错误简化为只剩系统朗读。

**决定**：

- 历史原文与关系记忆总结分开保存。每次导入只新增、去重原文，不自动制造描述或总结。
- 旧有或用户创建的总结可替换、可删除；操作前保留可回滚版本，原文证据始终独立保留。
- 每次导入都重新列出本次记录中的明确说话人。AI 开启时只用候选名称和每人最多三条短样例给建议，最终必须由用户确认。
- 无明确说话人字段时，不猜测双方身份；原文仍可保存与搜索。
- 语音保留两条路径：免费的 macOS 系统朗读，以及用户自备百炼 API Key 和音色 ID 的复刻声音。
- 公开仓库不携带私人音色 ID 或密钥；云端语音失败时自动回退系统朗读，文字功能不受影响。
